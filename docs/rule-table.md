# Rule Table (BrewIQ v0.1)

원본: `BrewIQ_RuleTable_v0.1.xlsx` (팀장 로컬 보관, 레포 미포함)
이 문서가 **구현 기준**입니다. 엑셀과 이 문서가 다르면 팀에 알리고 양쪽을 함께 고칩니다.

Rule Engine은 백엔드(`backend/app/services/rule_engine.py`)에 **단일 구현**으로 둡니다. 프론트에 같은 계산을 복제하지 않습니다.

---

## 1. 입력 / 출력

### 입력

| 변수 | 타입 | 값 |
|---|---|---|
| 생산 지역 | 선택 | 아프리카 / 중미 / 남미 / 아시아·태평양 |
| 가공방식 | 선택 | 워시드 / 내추럴 |
| 로스팅 레벨 | 선택 | 라이트 / 미디움 / 다크 |
| 분쇄 입자 D50 | 실수 (μm) | 카메라(ArUco) 측정 또는 수동 입력 |
| 원두량 | 정수 (g) | 사용자 입력 |
| 음용 방식 | 선택 | 핫 / 아이스 → Ratio 자동 결정 |

추출 **후** 입력 (Feedback):

| 변수 | 값 |
|---|---|
| 신맛 | 강함 / 만족 / 약함 |
| 쓴맛 | 강함 / 만족 / 약함 |
| 농도 | 진함 / 만족 / 연함 → Ratio 누적 보정 |

### 출력

| 출력 | 타입 |
|---|---|
| 권장 물 온도 | 정수 (℃) |
| 총 목표 물량 | g |
| 권장 분쇄도 방향 | 텍스트 (상대값, "N단계 굵게/곱게") |
| Target Curve | `(시간(초), 누적 물량(g))` 시퀀스 |
| 아이스 안내 메시지 | 아이스 선택 시만 |

## 2. 고정 상수

```python
BLOOM_POUR_SEC = 10        # Bloom 푸어 시간, 모든 레시피 동일
POUR_COUNT = 4             # Bloom 포함 (Bloom·2차·3차·4차)
RATIO = {"핫": 15, "아이스": 10}          # 1 : N, 농도 피드백으로 누적 조정
D50_RANGE = {"핫": (900, 1100), "아이스": (800, 1000)}   # μm
FLOW_MIN, FLOW_MAX = 2.5, 8.5             # g/sec 클램핑
```

## 3. 물 온도

```
물 온도 = 기본값(로스팅) + 지역 보정 + 가공방식 보정
```

| 기본값 | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| | 94 | 91 | 88 |

| 지역 보정 | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| 아프리카 | +2 | +2 | +1 |
| 중미 | 0 | 0 | 0 |
| 남미 | −1 | −1 | −1 |
| 아시아·태평양 | 0 | 0 | 0 |

| 가공방식 보정 | 전 레벨 |
|---|---:|
| 워시드 | 0 |
| 내추럴 | −1 |

---

## 4. Bloom

```
Bloom 물량(g) = 원두량 × 배수
Bloom 푸어 종료 = 10초
Bloom 대기 종료 = 10 + 대기 시간
```

| | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| 물량 배수 | 3.0 | 2.5 | 2.0 |
| 대기 시간(초) | 35 | 30 | 25 |

---

## 5. 유량 속도

```
유량 = clamp(기본값(로스팅) + 지역 보정 + D50 보정, 2.5, 8.5)   # g/sec
```

| 기본값 | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| | 4.0 | 5.5 | 7.0 |

| 지역 보정 | 전 레벨 |
|---|---:|
| 아프리카 | −1.0 |
| 중미 | 0 |
| 남미 | +1.0 |
| 아시아·태평양 | 0 |

| D50 보정 | 전 레벨 |
|---|---:|
| D50 < 기준 하한 (곱게) | +1.0 |
| 기준 범위 내 | 0 |
| D50 > 기준 상한 (굵게) | −1.0 |

## 6. 주수 배분과 타이밍

```
총 물량   = 원두량 × Ratio
남은 물량 = 총 물량 − Bloom 물량
2차 = 남은 물량 × 0.40
3차 = 남은 물량 × 0.33
4차 = 남은 물량 × 0.27   ← 반올림 오차 흡수를 위해 잔량으로 계산

푸어 시간 합 = 남은 물량 ÷ 유량
주수 간 대기 = (총 추출 목표 시간 − 10 − Bloom 대기 − 푸어 시간 합) ÷ 2
```

| 총 추출 목표 시간(초) | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| | 205 | 185 | 155 |

타임라인:

| 지점 | 계산 |
|---|---|
| 2차 시작 | 10 + Bloom 대기 |
| 2차 종료 | 2차 시작 + 2차 물량 ÷ 유량 |
| 3차 시작 | 2차 종료 + 주수 간 대기 |
| 3차 종료 | 3차 시작 + 3차 물량 ÷ 유량 |
| 4차 시작 | 3차 종료 + 주수 간 대기 |
| 4차 종료 | 4차 시작 + 4차 물량 ÷ 유량 (≈ 총 추출 목표 시간) |

Target Curve는 위 8개 지점을 `(시간, 누적 물량)`으로 잇는 **구간 선형(piecewise linear)** 곡선입니다. 대기 구간은 누적 물량이 유지되는 수평선입니다.

## 7. 검증 예시 (회귀 테스트 기준값)

입력: 원두량 20 g / 핫 / 라이트 / 아프리카 / 워시드 / D50 950 μm

| 항목 | 값 | 계산 |
|---|---:|---|
| 물 온도 | 96 ℃ | 94 + 2 + 0 |
| 총 물량 | 300 g | 20 × 15 |
| Bloom 물량 | 60 g | 20 × 3.0 |
| 유량 | 3.0 g/s | 4.0 − 1.0 + 0 |
| 남은 물량 | 240 g | 300 − 60 |
| 2/3/4차 물량 | 96 / 79 / 65 g | 240 × 0.40 / 0.33 / 잔량 |
| 푸어 시간 합 | 80 초 | 240 ÷ 3.0 |
| 주수 간 대기 | 40 초 | (205 − 10 − 35 − 80) ÷ 2 |

Target Curve:

```
(0,0) (10,60) (45,60) (77,156) (117,156) (143,235) (183,235) (205,300)
```

이 값은 파이썬 참조 구현으로 **전 항목 일치 확인 완료**입니다. Phase 3에서 `pytest` 회귀 테스트로 그대로 고정하세요.

## 8. 확인이 필요한 사항 (구현 전 팀 합의)

1. **주수 간 대기가 음수가 될 수 있음.**
   원두량이 커지면 푸어 시간 합이 총 추출 목표 시간을 넘어 대기가 음수가 되고, 타임라인이 역행합니다.
   최악 조합(핫 · 아프리카 · 굵은 분쇄 = 유량 최저)에서 음수가 시작되는 원두량:

   | | 라이트 | 미디움 | 다크 |
   |---|---:|---:|---:|
   | 핫 | 34 g | 41 g | 47 g |
   | 아이스 | 58 g | 발생 안 함 | 발생 안 함 |

   대응 후보: (a) 입력 원두량 상한(예: 핫 30 g), (b) 대기 하한 0초로 클램프 후 총 시간을 늘림, (c) 유량을 역산해 총 시간을 맞춤. **(b)와 (c)는 총 추출 시간 의미가 달라지므로 팀 결정 필요.**

2. **반올림 규칙 미정.** 물량은 정수 g, 시간은 소수 첫째 자리로 제안. 4차 물량만 잔량 처리해 총합을 보존합니다.

3. **농도 피드백의 Ratio 누적 조정 폭이 미정.** 1회당 ±0.5인지 ±1인지, 상·하한이 있는지 정해야 Phase 4를 시작할 수 있습니다.

4. **신맛/쓴맛 피드백 → 파라미터 매핑 테이블이 v0.1에 없습니다.** 개발계획서에는 방향(쓰다→유량↑·분쇄 굵게·온도↓)만 있고 수치가 없습니다. 충돌 우선순위는 `농도 > 균형감(신맛·쓴맛) > 단맛`으로 정해져 있습니다.

5. **"권장 분쇄도 방향"의 단계 정의.** D50 기준 범위 대비 몇 μm 차이를 1단계로 볼지 정해야 텍스트를 생성할 수 있습니다.

6. **초기값은 문헌 기반**입니다. Phase 1 실측 후 보정 예정이므로, 상수는 코드에 흩뿌리지 말고 한 모듈에 모아 두세요.
