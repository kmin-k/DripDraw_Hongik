## 4. Bloom

```
Bloom 물량(g) = 원두량 × 배수
Bloom 푸어 종료 = 10초
2차 시작 = 주수 간격 (6절)
```

| | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| 물량 배수 | 2.8 | 2.5 | 2.2 |

참고 레시피의 뜸 물량은 원두량의 **2.0~3.5배**(핫 평균 2.9배)였습니다.
Bloom 대기는 별도 상수가 아니라 `주수 간격 − 10초`로 자연히 정해집니다.

## 5. 유량 속도

```
유량 = clamp(기본값(로스팅) + 지역 보정 + D50 보정, 5.0, 12.0)   # g/sec
```

| 기본값 | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| | 7.0 | 8.0 | 9.0 |

v0.1의 4.0/5.5/7.0은 실사용의 절반 수준이라 "너무 살살 붓는" 곡선이 나왔습니다.
규칙만으로 나올 수 있는 범위는 **5.0~11.0**이고, 클램프는 피드백 누적 조정을 위한 안전장치입니다.

| 지역 보정 | 전 레벨 |
|---|---:|
| 아프리카 | −1.0 |
| 중미 | 0 |
| 남미 | +1.0 |
| 아시아·태평양 | 0 |

| D50 보정 | 전 레벨 |
|---|---:|
| D50 < 기준 하한 (곱게) | +1.0 |
| 기준 범위 내 | 0 |
| D50 > 기준 상한 (굵게) | −1.0 |

## 6. 주수 배분과 타이밍

```
총 물량   = 원두량 × Ratio
남은 물량 = 총 물량 − Bloom 물량
2차 = 남은 물량 × 0.40
3차 = 남은 물량 × 0.33
4차 = 남은 물량 × 0.27   ← 반올림 오차 흡수를 위해 잔량으로 계산

```

### 주수는 고정 간격으로 시작합니다

참고 레시피 15종 중 **13종이 30초 간격**으로 주수했고, 여러 곳이 *"30초마다 물 붓기"*라고 명시했습니다.

| 주수 간격(초) | 라이트 | 미디움 | 다크 |
|---|---:|---:|---:|
| | 35 | 30 | 25 |

타임라인:

| 지점 | 계산 |
|---|---|
| 뜸 시작 / 종료 | 0 / 10초 |
| 2차 시작 | 간격 × 1 |
| 3차 시작 | 간격 × 2 |
| 4차 시작 | 간격 × 3 |
| 각 주수 종료 | 시작 + 물량 ÷ 유량 |
| **총 추출 시간** | **4차 시작 + 드립다운(60초)** |

**대기 시간을 따로 계산하지 않습니다.** 간격에서 푸어 시간을 뺀 나머지가 곧 대기입니다.

> **v0.1에서 바뀐 핵심** — 이전에는 대기를 `(총 시간 − …) ÷ 2`로 역산했습니다.
> 그러면 유량을 올릴수록 푸어가 짧아지고 **남는 시간이 전부 대기로 흘러가** 더 오래 기다리게 됩니다.
> 실제 추출과 반대로 움직이는 모델이었습니다.

### 드립다운

마지막 주수를 시작한 뒤 물이 다 빠질 때까지의 시간입니다. 참고 레시피에서 "마지막 주수 시작 → 추출 종료"가 **평균 60초**였습니다.

Target Curve는 주수 8개 지점에 **드립다운 끝점 1개를 더해 9개 점**을 잇는 **구간 선형(piecewise linear)** 곡선입니다. 대기와 드립다운 구간은 누적 물량이 유지되는 수평선입니다. 드립다운을 곡선에 포함하면 화면에 "이제 기다리세요"가 그대로 보입니다.

## 8. 결정 사항

### 8-1. 원두량 상한 30 g (푸어가 주수 간격을 넘지 않도록)

**문제**

한 번에 붓는 양은 원두량에 정비례하는데 **주수 간격은 상수**입니다.
따라서 원두량이 커지면 어느 지점에서 푸어 시간이 간격을 넘고, **다음 주수가 이전 주수보다 먼저 시작**해 시간축이 역행합니다.

```
푸어 시간 = 원두량 × (Ratio − Bloom 배수) × 0.40 ÷ 유량   ← 원두량에 비례
주수 간격 = 로스팅별 상수                                  ← 고정
```

가장 많이 붓는 **2차(남은 물량의 40%)**가 기준입니다.

**임계값** — 최악 조합(핫 · 아프리카 −1.0 · 굵은 분쇄 −1.0 = 유량 최저)

| | 유량 | 간격 | 1 g당 2차 푸어 시간 | 임계 원두량 |
|---|---:|---:|---:|---:|
| 라이트 | 5.0 g/s | 35초 | (15−2.8)×0.40÷5.0 = 0.976초 | **35.9 g** |
| 미디움 | 6.0 g/s | 30초 | (15−2.5)×0.40÷6.0 = 0.833초 | **36.0 g** |
| 다크 | 7.0 g/s | 25초 | (15−2.2)×0.40÷7.0 = 0.731초 | **34.2 g** |

아이스(Ratio 10)는 물량이 적어 임계값이 훨씬 높습니다.

**결정**

입력 원두량에 **상한 30 g**을 둡니다 (`DOSE_MAX_G = 30`).

- 전역 최소 임계값이 다크·핫의 34.2 g이므로 30 g이면 **모든 조합에서 안전**합니다 (여유 4.2 g).
- v0.2에서 유량이 빨라져 임계값이 v0.1(34/41/47 g)보다 **오히려 균일해졌습니다.**
- 대안이었던 "간격을 물량에 따라 늘리기"는 참고 레시피의 **고정 30초 간격**이라는 근거와 어긋나 채택하지 않았습니다.

**구현**

- 프론트: 원두량 입력을 30 g에서 막고, 상한임을 UI에 표시
- 백엔드: Pydantic `le=30` 검증(422) + 엔진에서 푸어/간격 초과 검사(400) — [`api.md`](api.md) 참고
- 아이스도 **동일하게 30 g**을 적용합니다. 음용 방식마다 상한이 다르면 UI와 검증이 복잡해집니다.

**트레이드오프** — 3~4인분(30 g 초과)은 지원하지 못합니다. 데모 범위에서는 수용합니다.

### 8-2. 원두량 하한 10 g

**결정**: 입력 원두량 하한을 **10 g**으로 둡니다 (`DOSE_MIN_G = 10`).

상한과 달리 **수학적 필요가 아니라 실용적 판단**입니다. 원두량이 작아도 규칙식은 깨지지 않고 주수 사이 대기만 길어집니다. 하한을 두는 이유는 다음과 같습니다.

- 1잔 기준 실사용 최소치가 10 g 내외입니다. 그 미만은 현실적인 레시피가 아닙니다.
- 원두량이 극히 작으면 Bloom 물량도 함께 줄어(5 g·라이트 기준 15 g) 원두를 고르게 적시지 못합니다. Rule Table이 전제하는 추출 모델이 성립하지 않습니다.
- `0`이나 음수 입력을 차단하는 방어선이 필요합니다.

**구현**: 프론트 입력 제한 + 백엔드 Pydantic `ge=10`. 미만 시 `400`.

**재검토 조건**: Phase 1 실측에서 10 g 미만 추출이 유의미하다고 판단되면 완화합니다. 상한과 달리 낮춰도 곡선이 깨지지 않으므로 변경 비용이 낮습니다.

### 8-3. 반올림 규칙

| 대상 | 규칙 |
|---|---|
| 물량 | **정수 g** |
| Target Curve의 시간 | **정수 초** |
| 4차 물량 | **잔량으로 계산** — `총 물량 − Bloom − 2차 − 3차` |
| 반올림 방식 | **half-up** (0.5는 올림) |

4차만 잔량 처리하는 이유는 2·3차 반올림 오차가 총합을 어긋나게 하지 않도록 흡수하기 위함입니다.
7절 검증 예시와 일치합니다 — 240 × 0.40 = 96, 240 × 0.33 = 79.2 → 79, 잔량 = 240 − 96 − 79 = **65**.

**구현 시 주의 2가지**

1. **내부 계산은 반올림하지 않고 실수로 유지하고, 최종 출력에서만 반올림합니다.**
   주수 간 대기를 먼저 정수로 만든 뒤 타임라인에 누적하면 오차가 쌓여 마지막 점이 총 추출 시간에서 밀립니다.
   7절 예시의 3차 종료는 143.33초이고, 이를 누적에 그대로 쓴 뒤 출력만 반올림해야 `(143, 235) (183, 235) (205, 300)`이 나옵니다.

2. **파이썬 기본 `round()`를 쓰지 마세요.** 은행가 반올림(0.5를 짝수로)이라 엑셀 `ROUND`와 어긋납니다.
   원본이 엑셀이므로 `Decimal(...).quantize(..., ROUND_HALF_UP)`으로 맞춥니다.

### 8-4. 농도 피드백의 Ratio 조정 폭

```python
RATIO_STEP = 1.0                           # 1회 피드백당 조정 폭
RATIO_RANGE = {"핫": (12, 18), "아이스": (7, 13)}   # 기본값 ±3
```

- 농도 **연함** → Ratio − 1.0 (물량 감소 → 진해짐) / 농도 **진함** → Ratio + 1.0
- 농도 **만족**은 조정하지 않습니다 (dead zone)

**±1.0을 고른 이유**: 원두량 20 g 기준 총 물량이 300 g → 280 g으로 20 g 변합니다. ±0.5(10 g, 3.3%)는 사용자가 맛 차이를 못 느껴 "안 변했다"고 인식할 위험이 있고, `changes` 표에 `15 → 14`로 정수 표시되는 편이 발표에서 명확합니다. 진동(oscillation) 우려는 dead zone으로 완화합니다.

**상·하한을 둔 이유**: 반복 피드백 시 Ratio가 무한 발산하는 것을 막습니다. 기본값 ±3이므로 각 방향 3회까지 조정 여지가 있고, 데모 시연(1~2회)에는 충분합니다.

**⚠️ 재발 방지 (구현 완료)**: 8-1절의 상한 30 g은 **Ratio 15 기준** 계산입니다. Ratio가 피드백으로 오르면 한 번에 붓는 양이 늘어 임계값이 내려갑니다 — 예: 라이트·핫·유량 5.0에서 Ratio 18이면 임계값이 약 28.8 g이 되어, 원두량 29~30 g 레시피에서 **푸어가 간격을 넘습니다.** 따라서 **Ratio를 올리는 조정은 적용 전에 푸어 시간을 재계산**하고, 간격을 넘으면 해당 조정을 적용하지 않고 `notice`로 안내합니다 ("현재 원두량에서는 물을 더 늘릴 수 없어요"). Ratio를 내리는 조정은 항상 안전합니다.

같은 이유로 **유량을 낮추는 조정**도 막힐 수 있습니다. 같은 물량을 붓는 데 더 오래 걸리기 때문입니다. 구현은 두 조정을 함께 검사하고, 걸린 쪽만 되돌립니다.

실측 범위에서 한 번의 피드백(15 → 16)만으로는 어떤 조합에서도 간격을 넘지 않습니다. **같은 방향 피드백이 두 번 쌓였을 때** 걸립니다.

### 8-5. 분쇄도 1단계 = 50 μm

```python
GRIND_STEP_UM = 50
```

기준 범위 폭 200 μm(핫 900~1100)를 4단계로 분할합니다. 수동 그라인더 1클릭(약 30~40 μm)과 전동 그라인더(더 큼)의 중간값이라 특정 기구에 종속되지 않습니다.

**분쇄도는 누적 상태로 저장하지 않습니다.** 시스템이 그라인더를 제어할 수 없으므로 `"2단계 곱게"` 같은 **안내 텍스트만 출력**하고, 다음 추출 시에는 사용자가 입력(또는 Vision 측정)한 실제 D50을 그대로 사용합니다.

### 8-6. 맛 피드백 → 파라미터 매핑 (v0.1)

**문헌 근거가 없는 영역입니다.** 추출 이론상의 방향만 확립돼 있어 조정 폭은 보수적으로 시작하고, Phase 1 실측 후 튜닝합니다.

```python
TEMP_STEP_C   = 1      # ℃
FLOW_STEP_GPS = 0.5    # g/s
GRIND_STEP    = 1      # 단계 (= 50 μm, 8-5절)
TEMP_RANGE    = (85, 96)   # 유량은 기존 FLOW_MIN/MAX 5.0~12.0 유지 (8-8절에서 재조정)
```

| 피드백 | 해석 | 물 온도 | 유량 | 분쇄도 |
|---|---|---:|---:|---|
| 쓴맛 강함 | 과다추출 | −1 ℃ | +0.5 | 1단계 굵게 |
| 신맛 약함 | 과다추출 | −1 ℃ | +0.5 | 1단계 굵게 |
| 신맛 강함 | 과소추출 | +1 ℃ | −0.5 | 1단계 곱게 |
| 쓴맛 약함 | 과소추출 | +1 ℃ | −0.5 | 1단계 곱게 |
| 만족 | — | 0 | 0 | 유지 |

**충돌 처리**

- **반대 방향 동시 (신맛 강함+쓴맛 강함, 신맛 약함+쓴맛 약함)**: 과소·과다추출 신호가 공존하므로 **상쇄하고 조정하지 않습니다.** 파라미터가 아니라 **분쇄 입도의 균일성 문제**일 가능성이 높아, 조정 대신 `"분쇄도 균일성을 확인해 보세요"` 안내를 출력합니다.
- **같은 방향 동시 (신맛 강함+쓴맛 약함 = 모두 과소추출, 그 반대 = 모두 과다추출)**: 조정을 중첩하지 않고 **1회만 적용**합니다. 신호가 둘이라고 ±2℃가 되지 않습니다.
- **농도 vs 균형감**: 농도는 `Ratio`만, 균형감은 `온도·유량·분쇄도`만 건드리므로 파라미터가 겹치지 않아 실제 충돌이 없습니다. 우선순위 `농도 > 균형감 > 단맛`은 향후 같은 파라미터를 두고 경합할 때의 규칙으로 유지합니다.
- 모든 조정 후 각 파라미터를 상·하한으로 클램프합니다.

**한계 명시** — 이 표는 실측 검증을 거치지 않은 v0.1 휴리스틱입니다. 발표에서도 "데이터 축적 후 학습 기반으로 전환"을 다음 단계로 제시합니다.

### 8-8. 실사용 피드백에 따른 v0.2 재조정 (2026-08-06)

v0.1 규칙으로 실제 추출해보니 **"너무 살살 붓고 오래 기다린다"**는 문제가 드러났습니다.
국내 로스터리 브루잉 가이드 **15종**을 대조해 아래를 바꿨습니다.

| 항목 | v0.1 | v0.2 | 참고 레시피 |
|---|---|---|---|
| 타이밍 모델 | 대기를 총 시간에서 역산 | **고정 간격 주수** | 15종 중 13종이 30초 간격 |
| 기본 유량 | 4.0 / 5.5 / 7.0 | **7.0 / 8.0 / 9.0** | 역산 시 5~8 g/s |
| Bloom 배수 | 3.0 / 2.5 / 2.0 | **2.8 / 2.5 / 2.2** | 2.0~3.5배 (핫 평균 2.9) |
| 물 온도 기본 | 94 / 91 / 88 | **94 / 93 / 92** | 전부 93~95 ℃ |
| D50 기준(핫) | 900~1100 | **950~1250** | 900~1350 μm |
| 총 시간 개념 | 마지막 주수 **종료** | 마지막 주수 **시작 + 60초** | 평균 60초 |
| Ratio | 핫 15 / 아이스 10 | **유지** | 핫 1:15~17, 아이스 1:9.5~11.5 |

**모델 변경이 핵심입니다.** 상수만 고쳐서는 해결되지 않았습니다 —
대기를 역산하는 구조에서는 유량을 올릴수록 남는 시간이 대기로 흘러가 **더 오래 기다리게** 됩니다.

**근거의 성격이 바뀌었습니다.** v0.1은 문헌 기반 엑셀이 근거였고, v0.2는 **실사용 + 상용 레시피 대조**가 근거입니다. 후자가 더 강한 근거이므로 엑셀 원본은 기준에서 내렸습니다.
